> 지금 당장은 아니지만 나중에 다룰 것들. 흩어지지 않게 한 곳에 모음.

## 1. 확장성 (Scaling) — 사용자가 늘면

현재는 **단일 Node 서버 + Socket.IO(메모리 기반 온라인/전투 추적)**. 출시 초기 수백~1천 명 동접은 충분. 그 이상에서 손볼 것:

### 1-1. 부하 경감 (값싼 개선 — 미리 해둬도 무방)
- 전투 상태 동기화 주기를 0.15초 → 0.2~0.3초로 늘리기 (PvP 메시지량 직접 감소)
- 상태 전송을 "변화가 있을 때만"(델타 전송)으로 — 매 틱 전체 전송 대신 바뀐 탑만
- 생태계 틱 쿼리 인덱스 점검 (cells.owner_id, cells.tribe 이미 인덱스 있음 — 데이터 커지면 재확인)
- 지도 영역 조회(/cells) 폴링 주기 조정 (현재 8초)

### 1-2. 수직 확장 (간단)
- Railway 인스턴스 사양 상향 → 코드 변경 없이 2~4배 여유

### 1-3. 수평 확장 (큰 작업 — 동접 수천 이상)
- **Socket.IO + Redis 어댑터** 도입: 온라인 추적(현재 메모리 Map)과 전투 방을 여러 서버 인스턴스가 공유해야 함. 안 하면 도전자/방어자가 다른 인스턴스에 붙으면 서로 못 찾음.
- 온라인 추적(`onlinePlayers`)·대기 도전(`pendingChallenges`)을 Redis로 이전
- 지역(region) 구독을 현재 "전체 한 방"에서 지오해시 기반 방으로 분할

### 1-4. Firebase 옵션
- 초기 요구사항이었던 Firebase 실시간 DB를 Socket.IO 대신/병행 사용하는 선택지. Firebase는 실시간 동기화·확장을 자동 처리하나, 빠른 전투 입력 중계엔 다소 무거움. 현재는 Socket.IO 채택.

## 2. PvP 실시간 전투 — 견고화

현재: 도전자 온라인 + 수락 시 사람 대 사람, 미응답(15초)/거절/오프라인 시 AI 폴백. 양쪽이 자기 진영 상태를 0.15초마다 권위 동기화.

- **결과 부정 방지**: 현재 도전자 보고 승자를 신뢰. 양쪽 보고를 대조하거나, 서버가 전투를 권위 시뮬레이션하여 검증하는 로직 강화 필요.
- **네트워크 흔들림 대응**: 상태 불일치/지연 보정(보간, 재전송) 미구현.
- **재접속 처리**: 전투 중 한쪽이 끊기면? (현재 미처리 — 타임아웃 승패 또는 AI 인계 등 정책 필요)
- **관전 모드**: 같은 영역 다른 플레이어가 전투를 지켜보기.

## 4. 게임 기능 — 명세서엔 있으나 미구현

## 5. 신(神) 게임 모드 — 차기 방향 (별도 게임 가능성)

시뮬레이션 단계에서 깊이 탐색했으나 본류(GPS 매크로↔마이크로)에 집중하기 위해 보류. 핵심 설계는 잡혀 있음:

- **컨셉**: 신이 되어 3종족 생태계가 한 종족 지배로 붕괴하지 않게 유지. "지배=패배, 멸종=패배, 오래 버티기=점수" 랭킹 게임.
- **차별점** (기존 god game과): 가위바위보 상성 + 환생 영웅 + "지배하면 유전다양성 붕괴로 전멸"이라는 역설.
- **개입**: 실시간으로 흐르다 위기에 정지·개입(쿨다운 제한). 카드 — 전염병(1등 누르기), 축복(약자 살리기), 영웅 강림, 천재지변(과밀 리셋), 풍요 등.
- **구현 메모**: "커진 종족이 다시 말살되는" 연쇄 붕괴 로직은 현 엔진에서 큰 변경 필요. 권장 순서 — ① 1종족이 지배해가는 시뮬 수치부터 만들고 ② 그 위에 "우세 종족의 반대편 약자 종족에서 영웅이 강림해 전투" 개입을 얹는다.
- **참고 게임**: Populous(원조), Black & White, WorldBox(역병·재해 개입), From Dust, Reus, Imbalanced(오래 버티기+신능력해금, 가장 근접), Eco Balance.
- **전제**: 이 방향은 GPS 위치 기반 정체성과 결별. 별도 2번째 게임으로 갈지 결정 필요.
- **원칙**: 작게 시작해 "재밌는지" 먼저 확인 후 확장. 지구맵+정치/경제/공해 등 대규모 시스템은 핵심 재미 검증 후에.

## 6. 매크로 생태계 — 시뮬 검증됐으나 서버 간이 구현

시뮬레이터(BW_밀도시뮬_시각화.html)에서 검증한 풀 생태계 대비, 서버(macro.js)의 ecosystemTick은 간이 버전:

- **밀도 기반 생산**: 시뮬엔 있으나 서버 틱은 "셀당 고정 수입"으로 간이화. 밀도-과밀 곡선을 서버에 이식 가능(비용 큼 — 셀 밀도 계산).
- **상성 경계 잠식(압박)**: 서버 틱에 자리만 있고 미구현. "압박만, 점유이전은 마이크로" 원칙대로 def_bet 약화 등으로 표현 가능.
- **환생 영웅 풀**: soul_pool 누적·자연사는 구현. 영웅 환생 확률 적용·약자 격차보정(gapBoost)은 서버에 미이식.
- **검증된 핵심 상수** (시뮬에서): 3종족 상성 균형 ~42%, 변동성 ~2.7%p / 전투승리→전사→영웅 경로 / 격차보정은 효과 작아 "약자 사기용"으로 약하게(gapBoost~2) 권장 / 잠식 강도 0.6 근처가 전투사·인구 균형점.

## 9. 신규 유저 경험 — "왜 재미있나" 메모

**진단 (2026-05-31):** 메커니즘은 깊이 있는데(클러스터·노른자·영웅 환생·도전 큐·종족 상성), 신규 유저가 첫 5분에 만나는 흐름은 *재미 없음*.

신규가 겪는 실제 흐름:
1. 닉네임 → 종족 받음
2. 빈 곳 탭 → 점유 (작은 원)
3. **"이제 뭐 해?"** — 안내 없음
4. 또 점유 → 또 원
5. 에너지 천천히 ↑ (잘 안 보임 — 이번 v19에서 일부 개선)
6. **적이 없음** — 도전·클러스터 화력·영웅 시스템 다 죽음
7. 끝

체크리스트 (왜 안 재밌나):
- [ ] *피드백 시각화*: 점유해도 그 자리에서 "뭐가 일어나는" 느낌 약함. → v19에서 부유 +N 텍스트, HUD 수입률, 셀별 수입 시트 추가. 부분 완료.
- [ ] *해야 할 일 안 보임*: 신규 가입자에게 "다음 액션" 안내(예: 첫 점유, 첫 도전 튜토리얼) 없음.
- [ ] *초기 적 부재*: 혼자 시작하면 도전할 데가 없음 → NPC AI 봇이 지도에 미리 깔려 있어야 도전·클러스터 메커니즘이 살아남.
- [ ] *프로그레션 마커 부재*: 글로리 외엔 "내가 어디까지 왔나" 보일 데 없음. 칭호 / 마일스톤 / 레벨 시스템.
- [ ] *부재 시 사건 모름*: 자는 동안 도전당하거나 잃었어도 알림 없음. 푸시 / 알림센터 (앱에 들어왔을 때 표시).
- [ ] *서사 부재*: 종족·영웅·환생 시스템에 스토리/세계관 텍스트 없음. 이름 그대로 던져짐.

**다음에 다룰 만한 작업 (재미·유지율 직결):**
1. 신규 가입 시 *지도에 시드 NPC 봇 셀* 3~5개 자동 생성 (도전·클러스터 즉시 가능)
2. *튜토리얼 워크플로*: 첫 점유 → 첫 도전 → 첫 영웅 등 단계별 안내
3. *알림센터*: 부재 중 도전당함 / 베팅 잃음 / 영웅 환생 → 앱 진입 시 모달
4. *칭호/마일스톤*: 첫 점유, 5승, 10영토, 영웅 환생 등에 영구 칭호 (현재 글로리만 있음)
5. *고스트 모드 데모*: 닉네임 입력 전 짧은 인터랙티브 데모 (3탭으로 매크로→마이크로 흐름 체험)

## 10. 보안 감사 결과 (출시 전 필수)

> 2026-05-27 보안 리뷰 결과. **모두 인증이 없어서 생기는 문제** — 인증(JWT/세션)을 붙이면 대부분 자동으로 닫힘.
> 친구·소수 테스트 동안은 즉시 익스플로잇 위험 낮음. 외부 공개 직전에는 Phase 0+1 반드시 완료.

### Phase 0 — 인증 없이도 즉시 가능한 1~2시간 작업
- **XSS (High)**: `public/js/app.js`의 `innerHTML` 8군데에 `username` 직접 보간 (`<svg/onload=...>` 23자로 24자 제한 우회). → 모두 `textContent`로 변경 + 서버에 username 정규식 `^[\p{L}\p{N}_\- ]{2,24}$` 추가
- **전투 결과 위조 (High)**: `POST /api/challenge/:id/resolve`가 본문 `pvpWinner`를 그대로 신뢰. → 항상 서버 `simulateBattle`로 판정. PvP는 양쪽 보고 대조하거나 서버 권위 시뮬로 대체
- **GPS 1km 우회 (High)**: `claimCell`이 `if (playerLoc && finite(...))`라 본문에서 빼면 통과. → `playerLoc` 필수 + 무효 시 거부
- **전 세계 셀 덤프 (Medium)**: `GET /api/cells`가 영역 크기 무제한. `minLat=-90&maxLat=90` 한 방에 모든 플레이어 GPS+username 노출. → 영역 크기 상한 (예: ≤ 0.5°×0.5°)
- **도전에 GPS 제약 없음 (Medium)**: `claim`엔 있는데 `startChallenge`엔 없음. → 동일 1km 반경 적용

### Phase 1 — 인증 도입 (반나절~1일, 본질적 해결)
- `/api/player` 응답에 서버 발급 비밀 토큰 추가 (세션 or JWT), 클라가 `localStorage`에 보관 후 모든 요청에 `Authorization: Bearer` 헤더
- Socket.IO 핸드셰이크에서 `io({auth: {token}})`로 검증, `socket.data.playerId`를 서버가 토큰에서 추출 (클라이언트 `player:online` 이벤트의 ID 무시)
- 모든 엔드포인트가 `playerId === session.playerId` 검증
- **이걸로 자동으로 닫히는 취약점**:
  - Vuln 1 계정 탈취 (`POST /api/player`로 누구든 됨)
  - Vuln 4 Socket 신원 위조 (`player:online` 임의 ID 등록)
  - Vuln 6 남의 큐 항목 취소
  - Vuln 8 skipRest 본문 신뢰
  - Vuln 11 무인증 battle 이벤트 (`battle:state`로 상대 시뮬 조작)

### Phase 2 — 방어 심화
- **CORS**: `app.use(cors())` → 운영 도메인만 화이트리스트. Socket.IO `origin: '*'` 도 같이
- **CSRF**: 토큰 기반 인증이면 자동 완화. 쿠키 인증으로 가면 SameSite=Lax + CSRF 토큰 필수
- **battleId 비추측**: 현재 BIGSERIAL이라 enum 가능. UUID로 변경하거나 토큰화

### 참고 — 보안 감사 시 검토한 파일과 라인
- `server/routes/api.js`: 모든 엔드포인트 (12, 19-26, 46-59, 62-68, 71-77, 88-94, 97-103, 37-43)
- `server/index.js`: 소켓 핸들러 (21, 32, 47-51, 107-122, 125-133, 144-146)
- `server/game/macro.js`: claimCell GPS 가드 (71-106), resolveChallenge (267-)

## 우선순위 제안 (참고)

1. **지금**: 단일 서버로 출시·실사용 데이터 수집. 부하 경감(1-1) 정도만 미리.
2. **외부 공개 직전**: 보안 Phase 0+1 (9장) 반드시 완료.
3. **사용자 늘면**: PvP 견고화(2), 무적시간대 등 핵심 기능(4).
4. **성공 후**: 수평 확장(1-3), 매크로 생태계 풀구현(6), 보안 Phase 2.
5. **별도 트랙**: 신 게임 모드(5)는 본류 안정화 후 또는 2번째 게임으로.
